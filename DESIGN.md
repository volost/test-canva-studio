# Студія шаблонів весільних сайтів — дизайн

Стан: затверджено власником 2026-11-20 («Затверджую»).
Підстава: розмова з власником 2026-11-20; перевірені факти — `handoff/PLAYBOOK.md` §4–5 (прогін 12.11),
`study/sage-linen/SPEC.md` §7, пам'ять проєкту.

## 1. Навіщо

Власник робитиме шаблони весільних сайтів у Canva на **власних скелетах**, щоб згодом продавати їх на Etsy.
Зараз студія має **тільки генерувати продукти в Canva**: з одного скелета робити нові візуальні стилі
якості не гіршої за «Sage & Linen» (12.11), покроково, із затвердженням власника на кожному кроці.

Скелет — сайт у Canva, який власник збирає вручну один раз: сторінки, секції, стилізовані текстові поля,
рамки під картинки, форма, вбудовані блоки, анімація конверта. Стиль — новий набір картинок, кольорів і
текстів поверх копії скелета.

## 2. Цілі, не-цілі, анти-цілі

**Цілі**
- Один скелет → скільки завгодно стилів; кожен стиль — окрема копія скелета в Canva.
- Покроково: стиль → картинки → тексти → запис у Canva → перевірка; власник затверджує кожен крок у студії.
- Шаблон конфігурований для покупця за правилами `SPEC.md` §7 (персональні дані — лише живий текст і лише
  там, де потрібні; широкі поля; стрес-тест довгими значеннями; `fields.json`; чеклісти в нотатках сторінок).
- Повторюваність: те, що 12.11 робилося вручну агентами, тепер іде за одним і тим самим порядком.

**Не-цілі зараз** (відкладено власником 2026-11-20 або моє рішення — позначено)
- Etsy: оголошення, мокапи, ціни, правила продажу (власник: відкласти, не досліджувати).
- PDF-гайд для покупця і посилання на шаблон (моє рішення: це частина продажу, тому теж відкладено;
  `fields.json` і чеклісти в нотатках сторінок лишаються, бо це частина самого шаблону).
- Автоматична побудова скелета; зміна шрифтів; адреси у вбудованих блоках; посилання на картинках;
  публікація — конектор цього не вміє (12.11), це ручна робота власника.
- Хмара, кілька користувачів, вхід із паролем: студія локальна, для одного власника.

**Анти-цілі** (провал, навіть якщо «працює»)
- Будь-який запис в оригінал скелета або в куплений шаблон `DAHarqlqips`.
- Два записи в один дизайн одночасно (пізніший збереження затирає раніший).
- «Готово» без перевірки: статус «застосовано» без порівняння прочитаного з планом.
- Стиль, який дійшов до Canva без затвердження власника.
- Видалення файлів, генерацій чи дизайнів студією; публікація сайту; надсилання форми.

## 3. Обмеження (перевірені 11–12.11, якщо не сказано інше)

- Конектор Canva **вміє**: замінювати фон секції, картинку в рамці, фото в масці (`update_fill`); замінювати
  текст зі збереженням шрифту (`replace_text`); колір/розмір/вирівнювання тексту; перефарбовувати фігури,
  лінії, одноколірні векторні елементи; редагувати клітинки таблиці (календар); переміщати форму і
  вбудовані блоки; змінювати порядок шарів; писати нотатки сторінок.
- Конектор **не вміє**: додати секцію, змінити розмір секції, видалити сторінку, вибрати шрифт, змінити
  форму/вбудовані блоки/анімації/посилання на картинках, показати посилання.
- Після `update_fill` обов'язково `crop_media` до точного cover-кадру (інакше картинка на ~11 px більша).
- Копії зберігають id елементів скелета — карта скелета придатна для всіх його копій.
- Великі результати `read-design` зберігаються у файл; сторінки з секціями не мають мініатюр — щоб побачити
  результат: commit → `export-design` PNG → завантажити → нарізати.
- ComfyUI потребує GPU і `localhost`, які пісочниця Claude Code ховає. Тому сервер студії і ComfyUI запускає
  власник у своєму Терміналі (поза пісочницею).
- Безкоштовного плану Canva достатньо, щоб робити і переглядати дизайн.
- Мова шаблонів — англійська (моє рішення; так зроблені Ivory Lace і Sage & Linen).
- Шрифти — шрифти скелета. Студія радить пару шрифтів до стилю і після запису дає чекліст ручної заміни
  (рішення власника 2026-11-20).
- Витрата: 12.11 один шаблон забрав ~8 % тижневого ліміту (з дослідженням і виправленнями); нова оцінка
  буде після першого прогону.

## 4. Підходи

| Підхід | Що це | Плюси | Мінуси | Рішення |
|---|---|---|---|---|
| A. Запис через Claude Code | Студія готує завдання, сесія Claude Code виконує його через конектор Canva | Шлях перевірено 12.11; без нових акаунтів; тексти теж пише Claude | Для кроків із Claude потрібна сесія Claude Code | **Обрано власником** |
| B. Студія пише в Canva сама | Власний застосунок у Canva Developer Portal + OAuth + інструменти MCP | Студія незалежна | Не перевірено; потрібен застосунок розробника; тексти — окремий API | Не обрано |

Як студія передає роботу Claude Code:
- **Скринька завдань** (зараз): студія кладе завдання у файл, власник пише в сесії одну команду (`/studio`),
  сесія виконує завдання і кладе результат назад. **Обрано власником.**
- **Кнопка** (пізніше): студія сама запускає Claude Code у фоні (`claude -p`). Перехід — лише після тесту,
  що фоновий запуск бачить конектор Canva. Програма командного рядка зараз є лише всередині десктопного
  застосунку (`~/Library/Application Support/Claude/claude-code-vm/2.1.328/claude`), не на PATH. **Не
  перевірено.** Формат завдань однаковий для обох способів.
- Відкинуто: сесія, що постійно перевіряє скриньку — витрачає ліміт у простої.

## 5. Як (вирішено)

### 5.1 Потік одного шаблону

| Крок | Хто робить | Що бачить і затверджує власник |
|---|---|---|
| 0. Скелет (раз на скелет) | Claude: завдання `map_skeleton` — читає дизайн, експортує сторінки, складає карту | Карту: список рамок і текстів із ролями, мініатюри секцій; виправляє ролі |
| 1. Стиль | Власник пише бриф; Claude: завдання `style_directions` — 2–3 напрями (палітра з ролями, опис, підказки для картинок, пара шрифтів) | Обирає напрям, править палітру й підказки |
| 2. Картинки | Студія сама: генерує в ComfyUI під кожну рамку (точна пропорція), вирізає фон, збирає конверт кодом, проганяє перевірки | Галерея: «прийняти» / «ще раз» / своя підказка на кожну картинку; аркуш-огляд усіх разом |
| 3. Тексти | Claude: завдання `write_texts` — формулювання під стиль, близької довжини до скелета; персональні дані лише в полях зі списку | Редагує кожен текст у студії; бачить попередження про довжину |
| 4. Запис у Canva | Claude: завдання `apply_canva` — копія скелета, кольори, тексти, картинки (`update_fill` + `crop_media`), конфігурованість, стрес-тест і відновлення, нотатки сторінок, `fields.json` | Натискає «Записати»; потім бачить звіт |
| 5. Перевірка | Claude: завдання `verify` — експорт сторінок, вимірювання, перевірка в повноекранному перегляді Canva (телефон і комп'ютер, аудит кнопок 9/9) | Сторінки, таблиця перевірок (пройшло/ні з числами), посилання на дизайн, чекліст шрифтів і ручних кроків |

Кожен крок має статус: чернетка → чекає Claude → готово до перегляду → затверджено. Наступний крок
відкривається лише після затвердження попереднього. Повернутися назад можна; тоді наступні кроки
позначаються як застарілі.

### 5.2 Скринька завдань

- Студія пише завдання в `studio/jobs/pending/<id>.json`: тип, шаблон, вхідні файли, обмеження.
- Команда `/studio` у сесії Claude Code (skill проєкту) бере найстаріше завдання, переносить його в
  `running/`, виконує, пише результат і нотатки в папку шаблону, переносить завдання в `done/` або
  `failed/` з причиною. Одне завдання за раз; у роботі з Canva — завжди одне.
- Студія показує стан завдань, перечитуючи папку.
- Кожне завдання для Canva несе жорсткі межі з PLAYBOOK §6: який дизайн можна редагувати; ніколи
  оригінал; не чіпати форму, вбудовані блоки, структуру конверта; без перегрупування і нових сторінок;
  без публікації; без видалень; дві однакові невдачі виклику — стоп і нотатка.

### 5.3 Дані

- `studio/skeletons/<skeleton>/` — id дизайну скелета, карта (`map.json`: на кожен слот — locator,
  тип картинка/текст/колір/таблиця, роль, розмір рамки, ширина колонки для телефона, чи персональне поле),
  експорти секцій.
- `studio/templates/<template>/` — бриф, обраний напрям (`style.json`), `assets/` + маніфест + аркуш-огляд,
  `texts.json`, id копії в Canva, результати кроків, `fields.json`, нотатки кожного завдання.
  Розкладка за зразком `study/sage-linen/`.
- Карта скелета — єдине місце, де живуть id елементів; решта коду від конкретного скелета не залежить.

### 5.4 Технічне

- Мова — Python; інтерфейс — сторінка в браузері на `127.0.0.1`. Моє рішення: стандартна бібліотека
  Python для сервера і звичайні HTML/JS без збірки, щоб нічого не встановлювати; обробка картинок —
  Python із середовища ComfyUI (там є PIL і numpy).
- Запуск — один скрипт, який власник виконує в Терміналі: стартує ComfyUI (якщо не запущений) зі
  шляхами моделей проєкту і сервер студії; друкує адресу студії та адресу ComfyUI для спостереження.
- Перевикористати й узагальнити скрипти Sage & Linen: `study/sage-linen/tools/*` (генерація, вирізання,
  конверт, маніфест, аркуш-огляд, перевірка картинок) і `study/sage-linen/canva/{facts,plan,final_check}.py`
  (факти дизайну, план правок, перевірка після запису); прибрати з них жорсткі id і шляхи.
- Кожна перевірка має контроль: перед тим як повірити «нуль знахідок», вона має знайти щось свідомо наявне;
  перевірка картинок має відхиляти навмисно погані файли.

### 5.7 Уточнення після рецензії (мої рішення, власник може змінити)

1. **Карта скелета загальна, не під Ivory Lace.** Схема `map.json` описує будь-який скелет (слоти з
   locator, типом, роллю, розміром); карту складає Claude читанням дизайну, тож вона не залежить від
   структури. Перша перевірка — на тестовій копії `DAHason1g_M`; екран виправлення ролей обов'язковий.
2. **Частина Claude — половина продукту і входить у поставку:** skill `/studio` у проєкті та інструкції до
   кожного типу завдання (`map_skeleton`, `style_directions`, `write_texts`, `apply_canva`, `verify`) з
   жорсткими межами і форматом результату. Запис у `.claude/skills` проєкту пісочниця Bash блокує —
   створення skill потребує дозволу власника під час будування.
3. **Захист оригіналів — у коді.** На кожен стиль `apply_canva` робить нову копію скелета і записує її id у
   шаблон; усі подальші завдання Canva дозволені лише на цей id. Студія відмовляє створити завдання, якщо
   ціль — id скелета або `DAHarqlqips`; skill перевіряє те саме ще раз перед відкриттям транзакції.
   Тестова копія для дослідів — лише за потреби, одна на скелет.
4. **Один процес під Python середовища ComfyUI** (`/Users/volost/ComfyUI-Installs/ComfyUI-test/ComfyUI/.venv/bin/python`,
   перевірено 2026-11-20: PIL 12.3.0, numpy 2.5.2). Шляхи (ComfyUI, моделі на `/Volumes/WoofData/ComfyUI/models`,
   порт) — в одному конфіг-файлі студії. Скрипт запуску перевіряє, що диск змонтовано.
5. **Завдання, що зависло в `running/`.** Студія показує час старту; поки є завдання Canva в `running/`,
   нове завдання Canva не створюється. `/studio` на старті спершу дивиться в `running/`: читає нотатки і
   поточний стан дизайну, продовжує або позначає `failed` з причиною — як у PLAYBOOK §6 про перезапуск.
6. **Де бігають перевірки.** Перевірки картинок (пропорція, прозорість, конверт, навмисно погані файли) —
   у студії. Перевірки, яким потрібні читання Canva і браузер (`facts`/`final_check`, контраст на експорті,
   аудит кнопок 9/9), запускає Claude у сесії тими самими Python-скриптами; студія показує їхній результат.
7. **`fields.json` і нотатки сторінок** генеруються скриптом із карти (позначки «персональне поле») і
   записаних текстів під час `apply_canva`; Claude перевіряє їх проти прочитаного дизайну.

Порт сервера; вигляд інтерфейсу; точна схема JSON завдань і карти; як часто студія перечитує скриньку;

## 7. Не перевірено — перевірити, не обіцяти

1. Фоновий запуск `claude -p` бачить конектор Canva (передумова для кнопки).
2. Автоматична карта скелета для скелета, якого ще не існує: ролі слотів на новому скелеті може знадобитися
   уточнити вручну — тому крок 0 має екран виправлення ролей.
3. Скільки ліміту і часу забирає один шаблон через студію.
4. Інструмент Canva `create-design` як джерело скелета — лише з дозволу власника (тест створить дизайн у
   його акаунті).
5. Ліцензія моделі Z-Image Turbo на комерційне використання (питання продажу, відкладено разом з Etsy).
